## 1. Архитектурная схема и структура модулей

Проект строится по принципам **Clean Architecture + MVI (Model-View-Intent)**:

```
app/
├── core/
│   ├── network/                  # sing-box C-JNI bindings, OkHttp 4, SSE Engine, FakeDNS
│   ├── database/                 # Room Database, SQLCipher шифрование, FTS5 поиск
│   ├── security/                 # Android KeyStore, EncryptedSharedPreferences
│   ├── theme/                    # Material 3 Monet ColorScheme, AMOLED Black, Typography
│   └── common/                   # TextCleaners (WYSIWYG), HapticEngine, ResultWrapper
├── data/
│   ├── repository/               # ChatRepositoryImpl, ModelRepositoryImpl, SettingsRepoImpl
│   ├── providers/                # Реализации: OpenAIProvider, ClaudeProvider, GeminiProvider, DeepSeekProvider
│   ├── session/                  # WebView Isolated Session Interceptor, CookieVault
│   └── vpn/                      # SubscriptionParser, LatencyTester, FailoverRouter, ConfigGenerator
├── domain/
│   ├── model/                    # Chat, Message, Attachment, ModelInfo, ProviderType, TabItem
│   ├── usecase/                  # SendMessageUseCase, StreamResponseUseCase, ProcessOutboxUseCase
│   └── prompt/                   # AttachmentPromptBuilder, SmartContextPruner
└── presentation/
    ├── onboarding/               # Первый запуск: Выбор провайдера / Авторизация
    ├── chat/                     # Экран чата: Floating Capsule, MessageList, StreamingCursor
    ├── attachments/              # Шторка добавления, чипы вложений, BottomSheet предпросмотра
    ├── browser/                  # Side-Sheet Peek Drawer, TabBar (до 10 вкладок), WebViewRunner
    ├── history/                  # Боковое меню: списки чатов (Сегодня, Вчера), FTS5-поиск
    └── settings/                 # Управление аккаунтами, ключами, серверами и темами
```

## 2. Сетевое ядро sing-box: In-App VPN, FakeDNS и Auto-Failover

### 2.1. Интеграция бинарных библиотек
* В проект подключается нативная библиотека `libbox.aar` (сборка `sing-box` на Go с поддержкой v2ray/xray протоколов).
* Поддерживаемые архитектуры: `arm64-v8a` (основная), `armeabi-v7a`, `x86_64` (для тестирования на эмуляторах).
* Ядро запускается в фоне внутри процесса приложения и поднимает локальные порты:
  * SOCKS5: `127.0.0.1:10808`
  * HTTP-прокси: `127.0.0.1:10809`
* Никаких системных диалогов на создание VPN-подключения (системный «ключик» в статус-баре не требуется).

### 2.2. Генерация JSON-конфигурации sing-box на лету
Приложение динамически формирует конфиг в оперативной памяти:
1. **Inbounds:** Слушатели `mixed` (SOCKS5/HTTP) на `127.0.0.1`.
2. **Outbounds:**
   * Список всех узлов из подписки `https://s.wistfalls.cc/fPLkfFpVXdgS3Fkp`.
   * Селектор `auto-best` с алгоритмом `urltest` (периодический опрос задержки).
   * Резервные прямые выходы `direct` и `block`.
3. **Route Rules:**
   * Домены `openai.com`, `chatgpt.com`, `anthropic.com`, `claude.ai`, `google.com`, `googleapis.com`, `deepseek.com` и **100% трафика встроенного браузера** принудительно направляются в селектор прокси.
   * Локальный служебный трафик направляется через `direct`.
4. **DNS и FakeDNS:**
   * Удаленный безопасный DoH (DNS over HTTPS) через Cloudflare (`https://1.1.1.1/dns-query`) для полного предотвращения утечек DNS-запросов провайдерам РФ.

### 2.3. Алгоритм Healthcheck и Auto-Failover
1. **Предпусковая проверка:** При запуске приложение проводит параллельный замер TCP Handshake до хостов `api.openai.com` и `claude.ai` через доступные узлы.
2. **Порог отсечки:** Узлы с задержкой выше 2500 мс или ошибками рукопожатия временно исключаются из активного пула.
3. **Бесшовное переключение при разрыве (Graceful Failover):**
   * Если во время стриминга ответа входящий сокет рвется, приложение не стирает уже полученную часть сообщения.
   * `FailoverRouter` переключает исходящий маршрут на следующий живой узел за <400 мс.
   * Приложение отправляет повторный запрос с контекстом, допечатывая ответ с места обрыва.
4. **Фоновое обновление:** Системный `WorkManager` раз в 24 часа скачивает свежий список серверов по ссылке подписки.

## 3. Модуль аутентификации: Сессии (Web-Session) и API-ключи

### 3.1. Режим API-ключей (1-в-1 как MargyCode)
* Пользователь вводит ключи в настройках: OpenAI API Key, Anthropic API Key, Google AI Studio Key, DeepSeek API Key.
* Ключи шифруются алгоритмом AES-256 GCM с помощью аппаратного чипа безопасности `Android KeyStore`.

### 3.2. Режим сессионного входа (Официальные аккаунты)
* Для каждого сервиса создается изолированный экземпляр `WebView` с выделенным каталогом профиля данных (`setDataDirectorySuffix`), чтобы куки разных аккаунтов не смешивались.
* **Claude (`claude.ai`):**
  * Вход через веб-интерфейс (Google Auth / Email).
  * Извлечение сессионной куки `sessionKey`.
  * Фоновый запрос на `https://claude.ai/api/organizations` для получения `organization_id`.
* **ChatGPT (`chatgpt.com`):**
  * Вход через веб-интерфейс.
  * Извлечение Bearer-токена `accessToken` через системный эндпоинт `https://chatgpt.com/api/auth/session`.
  * Перехват сессионной куки `__Secure-next-auth.session-token`.
* **Gemini (`gemini.google.com`):**
  * Вход через стандартную форму Google-аккаунта.
  * Перехват авторизационных кук `SID`, `HSID`, `SSID`, `__Secure-1PSID`.
  * Автоматическое извлечение параметра `SNlM0e` (токен безопасности сессии) из исходного кода веб-страницы через regex.
* **DeepSeek (`chat.deepseek.com`):**
  * Вход по логину/паролю или коду.
  * Извлечение токена `userToken` из `localStorage`.

### 3.3. Обработка протухания сессий
* Если сервер возвращает код `401 Unauthorized` или `403 Forbidden`, приложение выводит аккуратную неблокирующую плашку вверху экрана: `Сессия Claude требует подтверждения [Обновить]`.
* При нажатии открывается WebView, где пользователь подтверждает вход, и сессия бесшовно обновляется.

## 4. Динамический пул моделей, квоты и скользящий контекст

### 4.1. 100% динамическое определение моделей
* **Никаких захардкоженных списков.**
* Список моделей запрашивается напрямую с серверов провайдеров от имени учетной записи пользователя:
  * ChatGPT: `GET https://chatgpt.com/backend-api/models`
  * Claude: `GET https://claude.ai/api/organizations/{org_id}/models`
  * Gemini: эндпоинт внутренних сервисов или `GET https://generativelanguage.googleapis.com/v1beta/models`
  * DeepSeek: `/api/v0/models` или `/v1/models`
* В интерфейсе показываются **только те модели, которые фактически доступны текущему пользователю**.

### 4.2. Индикация лимитов и автоматический даунгрейд
* Если сервер отдает статус квот (например, оставшиеся сообщения или время сброса лимита), рядом с названием модели выводится процент расхода.
* **Автоматический даунгрейд:** Если во время работы лимит исчерпан, генерация не прерывается ошибкой — приложение автоматически переключает запрос на резервную модель аккаунта для завершения ответа.

### 4.3. Адаптивное скользящее окно контекста (Smart Context Pruning)
* Если пользователь переключает модель внутри одного чата (например, с Gemini 1M токенов на модель с 32k токенов):
  * Приложение рассчитывает суммарный вес истории.
  * Если контекст превышает допустимый лимит новой модели, алгоритм сохраняет:
    1. Системную инструкцию пользователя;
    2. Все прикрепленные вложения текущего запроса;
    3. Последние сообщения диалога (ровно столько, сколько помещается в 75% лимита целевой модели).

## 5. Система мультимодальности и уникальных вложений

### 5.1. Камера и изображения
* Интеграция `CameraX` для захвата фотографий в полном физическом разрешении сенсора.
* Передача изображений без сжатия, если это допускает API. Если размер файла превышает лимит провайдера (например, >20 МБ), активируется деликатное сжатие ровно до верхней границы лимита.

### 5.2. Система вложений (до 10 штук на сообщение)
* **Типы вложений:**
  * *Файлы:* PDF, DOCX, XLSX, TXT, CSV, JSON, файлы кода. Текст из документов извлекается локально на устройстве (через Android `PdfRenderer` и легковесный XML-парсер DOCX).
  * *Текстовые вложения (Raw Text):* Отдельное модальное поле для вставки скопированных статей, конспектов и логов.
* **Интерфейс:** Строгие системные чипы над полем ввода с указанием имени файла или объема текста и кнопкой удаления. Тап по чипу открывает Bottom Sheet предпросмотра.
* **Строгий утвержденный шаблон промпта:**
  ```text
  Вложение:
  {содержимое прикрепленного файла или текст из поля вложения}

  Сообщение пользователя:
  {основной текст из поля ввода}

  При работе учитывай и прикрепленные вложения и сообщение пользователя.
  ```

## 6. Встроенный Side-Sheet браузер и режим кнопки «Глобус»

### 6.1. Механика выдвижной панели (Split Side-Sheet)
* У правой кромки экрана расположен ненавязчивый индикатор-полоска (толщиной 20dp).
* Плавный свайп влево или тап раскрывает браузер на 80% ширины экрана, не закрывая контекст чата.
* Поддерживается **до 10 вкладок**, изолированных в рамках текущего чата (в новом чате открывается чистый браузер).
* **100% трафика браузера идет через встроенный прокси**, гарантируя открытие любых заблокированных зарубежных ресурсов.

### 6.2. Логика кнопки «Глобус»
* **Кнопка «Глобус» НАЖАТА (активна):**
  * Нейросеть **обязана** воспользоваться интернетом или проанализировать открытые вкладки встроенного браузера.
  * Приложение извлекает читаемый текст активной страницы (Readability-фильтрация на JavaScript) + делает скриншот страницы и автоматически отправляет их в модель.
* **Кнопка «Глобус» НЕ нажата:**
  * Нейросеть отвечает на базе собственных знаний (для экономии токенов и ускорения отклика).

## 7. Интерфейс в стиле Gemini (Material You 3 без визуального шума)

### 7.1. Строгий человеческий дизайн
* Никаких стикеров, эмодзи в интерфейсе и декоративного шума.
* Нативная типографика Google Sans / Roboto, векторные системные иконки Material Symbols.
* Поддержка двух вариантов тем:
  * **Material You Dynamic Gray:** Адаптация под системные обои (Monet Palette).
  * **True AMOLED Black:** Глубокий черный цвет (`#000000`) для экономии заряда батареи.

### 7.2. Плавающее поле ввода (Floating Input Capsule)
* Капсула со скруглением 28dp, парящая над нижним краем экрана.
* Полупрозрачный фон с эффектом аппаратного размытия `BackdropBlur(20.dp)`.
* Внутри капсулы: кнопка добавления вложения, кнопка «Глобус», поле ввода и кнопка отправки.

### 7.3. Стриминг и компонент «Размышления»
* Оптимизированный рендеринг стриминга: буферизация обновлений с шагом 16 мс для обеспечения стабильных 60/120 FPS без лагов интерфейса.
* Для моделей с рассуждениями (DeepSeek R1, Claude Thinking, o1/o3-mini) процесс оформляется в лаконичный спойлер: `Размышления • 8 сек [Развернуть]`.
* **Чистое копирование (WYSIWYG):** При нажатии «Копировать» удаляются все служебные теги `<think>`, внутренние метаданные и артефакты — копируется только визуально видимый чистый текст.
* **4 кнопки под ответом:** Копировать, Поделиться, Перегенерировать, Ответить другой моделью.
* **Тактильный отклик (Haptics):** Мягкие микро-вибрации при отправке, начале стриминга и завершении ответа.

## 8. Оффлайн-режим, Очередь (Outbox) и Foreground Service

### 8.1. Зашифрованное локальное хранилище Room (SQLCipher)
* Все диалоги, сообщения и вложения сохраняются в локальной базе данных с шифрованием AES-256.
* Полнотекстовый поиск FTS5 обеспечивает мгновенный поиск по всей истории переписок.
* **Режим «Инкогнито» (Временный чат):** База данных разворачивается в оперативной памяти (`inMemoryDatabaseBuilder`). При закрытии чата данные мгновенно стираются без записи на накопитель.

### 8.2. Очередь сообщений (Outbox Pattern)
* Если сеть отсутствует в момент отправки, сообщение сохраняется в локальной базе со статусом `OUTBOX_QUEUED`.
* Как только сетевой монитор фиксирует появление связи и доступность прокси, системный `WorkManager` автоматически отправляет сообщения из очереди.

### 8.3. Фоновый сервис (Foreground Service)
* Если пользователь свернул приложение или заблокировал экран во время генерации длинного ответа, активируется легковесный `Foreground Service`.
* В шторке уведомлений Android отображается статус генерации. Ответ гарантированно допечатывается до конца, а по завершении подается мягкий звуковой/тактильный сигнал.

## 9. Публичные веб-ссылки на чаты (Cloudflare Workers KV)

* Функция шеринга целого чата («Поделиться ссылкой как в Gemini»).
* При нажатии ветка сообщений очищается от персональных данных, сериализуется в JSON и отправляется на бесплатный микросервис Cloudflare Workers.
* Создается ссылка вида: `https://chat.hub.app/s/{hash}`.
* В любом браузере (на ПК, iPhone, Android) открывается адаптивная страница в стиле Material You с красивой подсветкой кода и возможностью копирования.

## 10. Сборка, ProGuard, дистрибуция и автообновление (In-App Updater)

### 10.1. Оптимизация сборки и ProGuard / R8
* Правила сжатия кода R8 настроены так, чтобы не удалять JNI-интерфейсы `libbox.so`, классы моделей данных Room и сериализаторы Kotlinx Serialization.
* Результат: компактный размер APK (ориентировочно 25–35 МБ с учетом всех нативных библиотек архитектуры arm64).

### 10.2. Каналы распространения
1. **GitHub Releases:** Основной репозиторий с автоматической публикацией сборок через GitHub Actions при создании нового тега.
2. **Прямая ссылка / Telegram-канал:** Быстрая загрузка без цензуры и региональных ограничений маркетов.
3. **RuStore & Obtainium:** Индексация в независимых каталогах.

### 10.3. Встроенный авто-обновлятор (In-App Auto-Updater)
* Приложение при старте проверяет GitHub Releases API на наличие новых версий.
* При выходе обновления в настройках появляется плашка: `Доступна версия 1.2.0 [Обновить]`.
* При нажатии приложение скачивает APK в кэш через системный `DownloadManager` и вызывает нативный интент установки:
  ```kotlin
  val intent = Intent(Intent.ACTION_VIEW).apply {
      setDataAndType(apkUri, "application/vnd.android.package-archive")
      flags = Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_GRANT_READ_URI_PERMISSION
  }
  context.startActivity(intent)
  ```
* Пользователь обновляет приложение в 1 клик с сохранением всех диалогов и ключей.
